# Разработка и проверка

## Открытие в IntelliJ IDEA

Откройте корневую папку `intercept-go` как проект. Нужен плагин Go; отдельные workspace-файлы IDE в Git не сохраняются. Модуль объявлен в `go.mod`, поэтому пакеты и тесты обнаруживаются автоматически.

## Обычная проверка

```powershell
$env:GOPATH = Join-Path (Get-Location) '.gopath'
$env:GOCACHE = Join-Path (Get-Location) '.gocache'
go test ./...
go vet ./...
```

Полная сборка выполняется `scripts/build-release.ps1`. Готовые файлы записываются рядом с проектом в `Intercept-Releases\<версия>`, а технический кэш — в `%LOCALAPPDATA%\InterceptGoBuild`. Поэтому после сборки корень исходного проекта остаётся чистым.

## Границы автоматической проверки

Автотесты проверяют чтение EAVC только для чтения, долговечные очереди, шифрование, проверку отправителя, одновременный приём трёх точек, строгую маршрутизацию, независимые доставки, DOCX, журналирование и чистый запуск архивов.

Проверка с настоящими Telegram-ботами, темами рабочей супергруппы и сетевой папкой выполняется лабораторным сквозным сценарием: секреты остаются только на настроенных ВМ и не попадают в репозиторий. `lab/Run-Code-Quality.ps1` проверяет контрольную сумму переносимого GCC, включает CGO только на время `go test -race ./...`, а затем собирает рабочие Windows EXE с `CGO_ENABLED=0`. Самим приложениям CGO не требуется.
