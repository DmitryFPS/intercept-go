# Безопасность

## Модель доверия

Telegram используется как доступный из интернета почтовый ящик транспорта, а не как хранилище открытых рабочих данных. Содержание пакета шифруется клиентом до отправки.

Telegram видит технические метаданные: время, размер файла, ID ботов, группу и тему. Содержание EAVC, название подразделения и текст перехвата находятся внутри AES-256-GCM шифротекста.

## Разделение ключей

- У каждой точки отдельный транспортный бот и отдельный ключ данных.
- Компрометация одной точки не раскрывает пакеты других точек.
- Ключ каждой точки имеет отдельный `key_id`. Текущая версия заменяет конфигурацию целиком; перекрывающаяся ротация нескольких действующих ключей пока не заявляется.
- Сервер хранит токены и ключи в защищённом локальном хранилище.
- Клиент после импорта защищает секреты через Windows DPAPI для текущего пользователя.
- Очереди событий, задания доставки, ключи клиентов и карантин в SQLite также
  шифруются DPAPI. Старые открытые записи защищаются при первом запуске новой версии.
- Каждый JSON клиента подписывается отдельным ключом центра Ed25519. При первом
  запуске готового комплекта клиент автоматически запоминает выдавший его центр,
  переносит JSON в DPAPI-хранилище и удаляет открытый файл. Последующие файлы
  другого центра отклоняются без участия оператора.

## Локальный интерфейс

Интерфейс слушает только `127.0.0.1`, но одного loopback-адреса недостаточно против
вредоносной страницы в браузере. При запуске программа открывает защищённую ссылку,
устанавливает `HttpOnly` cookie и далее проверяет точный `Host`, `Origin` и
`Sec-Fetch-Site`. Токен доступа хранится через DPAPI и не выводится в журнал.

## Ограничения Telegram

Для приёма сообщений от ботов точки серверный бот должен иметь включённый Bot-to-Bot Communication Mode. В транспортной группе он должен быть администратором либо работать с отключённым режимом приватности. Получение выполняется long polling; webhook на этом токене должен отсутствовать.

Программа не пытается угадать эту настройку по косвенным признакам. Кнопка проверки отправляет отдельный пакет клиентским ботом и ждёт личный ответ серверного бота. Служебный пакет проходит ту же проверку отправителя, группы и темы, но никогда не попадает в рабочие маршруты.

Транспортная супергруппа закрытая. В неё добавляются только администраторы и зарегистрированные боты. Обычные рабочие сообщения туда не пишутся.

Исходящие операции проходят через ограничитель частоты. Для одного группового
чата выдерживается не менее трёх секунд между новыми сообщениями, для личного
чата — не менее одной секунды, а общий темп одного бота остаётся ниже 30
сообщений в секунду. Полученный от Telegram ответ `429` и его `retry_after`
сохраняются в долговечной очереди: повтор выполняется не раньше указанного
Telegram времени и переживает перезапуск программы. Несколько получателей с
одним токеном используют один ограничитель.

## Защита от ошибок и повторов

- Ограничение размера применяется до чтения файла целиком.
- Метаданные бота, группы и темы проверяются до скачивания транспортного файла.
- MIME-тип и расширение не считаются доказательством корректности.
- Каждый пакет проходит проверку схемы и AEAD.
- Telegram sender ID, группа и тема сверяются с регистрацией точки.
- UUID события уникален; другое содержимое с уже известным UUID считается конфликтом и помещается в карантин.
- Логи маскируют токены, ключи, пароли и параметры URL.
- Карантин ограничивается сразу после каждой записи: не более 1000 пакетов и 64 МиБ.
- При чтении DOCX ограничиваются число частей и объём после распаковки, поэтому
  специально подготовленный ZIP не может бесконтрольно занять память.

## Резервное копирование

Для восстановления нужны серверная база состояния, ключи, опубликованные маршруты, шаблоны Word и настройки направлений. Резервная копия шифруется и проверяется тестовым восстановлением. Транспортная группа не является резервной копией системы.
