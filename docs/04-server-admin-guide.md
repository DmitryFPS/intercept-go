# Работа администратора с EAVC Connect — Центр управления

## Первый запуск

1. Распакуйте сервер в постоянную папку мини-ПК.
2. Положите рядом рабочий `word_template.docx`, если используется Word-направление.
3. Запустите `EAVC Connect Center.exe`.
4. Откройте раздел **Транспорт** и укажите токен серверного бота, ID закрытой транспортной супергруппы и необязательную ссылку-памятку.
5. Добавьте серверного бота администратором в транспортную супергруппу, дайте ему право удалять сообщения и включите для него Bot-to-Bot Communication Mode в BotFather.
6. Нажмите **Проверить и сохранить**. Сервер проверит токен, доступ к группе и отключит webhook перед запуском long polling.

## Добавление точки

Для трёх точек используются четыре учётные записи ботов: по одному боту для Текстиля, Селидово и Весёлого, а также один серверный бот. Существующего бота Аэродрома и Шабашки можно использовать как серверного, если старый Python-сервер с этим токеном полностью остановлен. Три клиентских бота нельзя заменять одним общим токеном: подтверждение может получить не тот компьютер.

Создание клиентского бота:

1. Откройте официального `@BotFather` и отправьте `/newbot`.
2. Задайте понятное имя и уникальное имя, оканчивающееся на `bot`.
3. Сохраните выданный токен и никому его не пересылайте, кроме администратора Intercept.
4. Отправьте `/mybots`, выберите бота, откройте **Bot Settings → Bot-to-Bot Communication** и включите режим.
5. Добавьте бота в закрытую транспортную супергруппу. Администратором клиентский бот быть не обязан; ему достаточно права отправлять файлы в тему своей точки.
6. Повторите действия для каждой точки. У серверного бота включите тот же режим и выдайте в группе права администратора, отправки и удаления сообщений.

В сервере откройте **Точки → Добавить точку** и укажите:

- понятное название;
- токен бота точки;
- тему транспортной группы;
- часовой пояс EAVC — обычно **Москва (UTC+3)**;

После сохранения точки нажмите **Скачать готовую программу**. Центр выдаст ZIP с
EXE, индивидуальным подписанным JSON и памяткой. Отправьте ZIP оператору по
электронной почте. Оператору достаточно распаковать всю папку на Рабочий стол и
запустить EXE: первичная настройка применяется автоматически.

Кнопка **Скачать новые настройки JSON** нужна только для последующих изменений.
Оператор загружает присланный JSON одноимённой кнопкой; файл другого центра будет
отклонён.

После запуска оператор нажимает **Проверить связь с центром**. Клиентский бот отправляет отдельный служебный файл в свою тему, бот центра получает его и отвечает клиентскому боту. Только появление времени **Связь проверена** подтверждает Bot-to-Bot в обе стороны. Проверочный файл не проходит маршрутизацию и не появляется у рабочих получателей.

Если проверка не завершилась:

1. Убедитесь, что Bot-to-Bot включён у обоих ботов.
2. Проверьте, что оба бота добавлены именно в транспортную группу.
3. Проверьте ID группы и ID темы точки.
4. Убедитесь, что старый сервер или другая программа не использует `getUpdates` или webhook с тем же токеном.
5. Скачайте диагностику клиента и сервера.

В списке добавленных точек видны номер, название, бот и тема. Готовый комплект и
тот же защищённо сохранённый JSON можно скачать повторно; создавать новую точку
для этого не нужно.

## Направления

Направление не связано с названием «Шабашка» или номером сети `313`. Это запись одного из типов:

- Telegram-группа или канал;
- Telegram-тема;
- Word в локальную или сетевую папку.

Для каждого направления есть собственные настройки, состояние, очередь и журнал. Новое направление ничего не получает, пока администратор явно не включит маршруты.

Поле **Обозначение радиосети** заполняется вручную и не определяется по названию получателя. Например, для Telegram можно указать `39`, а для Word — `313`. Это значение появится после названия радиосети в готовом сообщении или документе. Поэтому получатель может называться как угодно, а обозначение всегда остаётся явной настраиваемой величиной.

У Telegram-получателя есть отдельное поле **Шаблон сообщения Telegram**. Текст и оформление можно менять прямо в интерфейсе. Обязательные метки `{{UNIT}}`, `{{NETWORK}}`, `{{FREQUENCY}}`, `{{GROUP_ID}}`, `{{PROTECTION}}`, `{{DATE}}`, `{{CORRESPONDENTS}}` и `{{TRANSCRIPT}}` должны остаться в шаблоне: вместо них программа подставляет настройки получателя и данные EAVC. Кнопка **Восстановить стандартный** возвращает утверждённый формат. Сохранённый шаблон хранится вместе с настройками конкретного получателя в защищённом файле `data/server-config.dat`.

Для Word выбирается внешний DOCX. Программа больше не заменяет его тело своей разметкой: она сохраняет таблицы, поля, подписи, шрифты и другой неподвижный текст, а заменяет только метки `{{UNIT}}`, `{{NETWORK}}`, `{{FREQUENCY}}`, `{{GROUP_ID}}`, `{{DATE}}`, `{{CORRESPONDENTS}}`, `{{TRANSCRIPT}}` и `{{EDITED_MARK}}`. Последние три метки размещаются каждая в отдельном абзаце, потому что на их месте может появиться несколько строк. При сохранении получателя центр проверяет все метки и перечисляет отсутствующие. Стандартный файл можно восстановить кнопкой в форме, а выбранный — скачать из карточки получателя.

## Матрица маршрутов

В строках находятся позиции EAVC и системная строка неопознанных данных. В столбцах находятся направления. Каждая ячейка имеет одно из состояний:

- **Не отправлять**;
- **Отправлять**;
- **На проверку**.

Для Telegram-направления действие «Отправлять» также содержит тему. Для Word-направления оно содержит профиль шаблона и папки.

Изменения в таблице сначала являются локальным черновиком. Кнопка **Опубликовать новую версию** проверяет всю матрицу и атомарно включает её. В блоке истории можно восстановить предыдущую матрицу; восстановление сохраняется как новая версия.

## Разбор неопознанного события

Сервер отправляет исходное название в General направления, выбранного для действия **На проверку**, с красным заголовком. Если строка близка к известной, сообщение содержит подсказку. Администратор проверяет исходное название и при необходимости добавляет точную новую позицию в матрицу. Похожее название никогда не подставляется и не маршрутизируется автоматически.

На странице **Обзор** доступна кнопка **Скачать диагностику**. ZIP содержит безопасный статус, историю версий правил и ротируемые журналы, но не содержит токены, ключи или пароли.
