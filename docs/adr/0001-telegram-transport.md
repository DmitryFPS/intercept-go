# ADR-0001: закрытая Telegram-супергруппа как транспорт

- Статус: принято
- Дата: 2026-10-18

## Контекст

У серверного мини-ПК нет белого IP или домена. Точки подключены к интернету, но менять EAVC сейчас нельзя. Нужна переносимая программа без установки VPN и без входящих подключений.

Telegram Bot API поддерживает исходящие HTTPS-запросы, long polling и темы форумной супергруппы. Актуальная платформа также поддерживает Bot-to-Bot Communication Mode, поэтому серверный бот может получать сообщения от ботов точек при правильной настройке группы.

## Решение

Использовать одну закрытую форумную супергруппу и отдельную тему для каждой точки. У каждой точки отдельный бот-отправитель. У сервера отдельный бот-получатель. Пакеты шифруются приложением до Telegram.

## Последствия

Положительные:

- не нужен белый IP, VPN или проброс портов;
- каждая сторона выполняет только исходящие HTTPS-запросы;
- точки логически разделены темами и криптографическими ключами;
- новый клиент добавляется без изменения исполняемых файлов.

Ограничения:

- работа зависит от доступности Telegram;
- Telegram видит транспортные метаданные;
- Bot-to-Bot Communication Mode требуется включить вручную в BotFather;
- ссылка-приглашение не заменяет `chat_id`, токен и добавление бота в группу;
- при запрете Telegram нужен новый транспортный адаптер.

## Отклонённые варианты

- Прямой HTTP к мини-ПК: невозможен без доступного входящего адреса или туннеля.
- Один общий бот для отправки и приёма: хуже разделяет точки и усложняет подтверждения.
- Открытые сообщения в Telegram: не соответствуют требованию конфиденциальности.
- Пользовательская MTProto-сессия на сервере: требует телефонной авторизации и увеличивает эксплуатационную сложность; после появления bot-to-bot режима больше не является необходимой.
