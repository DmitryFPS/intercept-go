# Старая Python-версия и новая Go-версия

## Полная цепочка

Оператор создаёт или редактирует бланк в EAVC. `EAVC Connect — Рабочая точка` не управляет EAVC и не меняет его базу: он открывает `main.sqlite` только для чтения, читает запись `intercept_items`, делит содержание по строкам времени и дополняет блоки позывными из `intercept_callsigns`.

В старой версии клиент отправлял JSON по HTTP в локальной сети. В новой версии клиент сохраняет событие в собственной очереди, шифрует его индивидуальным ключом точки и отправляет файл `.icevent` ботом точки в её тему закрытой транспортной Telegram-группы. Серверный бот принимает файл, проверяет точку, тему, срок и подпись шифротекста, после чего создаёт независимые задания для Аэродрома, Шабашки, Word-направления с номером сети `313` и любых добавленных направлений.

## Что является идентификатором

- `intercept_items.id` и `intercept_items.uuid` обозначают запись перехвата EAVC, а не позицию.
- Позиция сейчас определяется значением `unit_name`. Если EAVC предоставляет `catalog_uuid`, клиент также передаёт его.
- Клиент присваивает каждой версии события UUID v7. Он используется для подтверждений, очередей и защиты от повторной обработки.
- Состояние опубликованных блоков привязано к UUID записи EAVC и ключу временного блока. Благодаря этому изменение одной реплики не создаёт второй полный набор сообщений.

## Формат Telegram-сообщения

Источник истины для оформления — утверждённый реальный пример Telegram. Номер радиосети задаётся отдельно у каждого получателя, а номер и описание корреспондента читаются из его карточки EAVC:

```text
Радиосеть Гольназ - 39
159.3000 МГц (ID 18902 AES-256)
20.10.2026г.

1. «Монако» (id: 52345) ОД на КНП Гольназ, мужской голос, украинская речь;
6. «Торба» (id: 52325) Старший группы Гольназ, мужской голос, украинская речь;

17:30
/6/ Монако Торбе на связь;
/1/ На связи.
```

Внутренний цифровой ID в скобках не остаётся в реплике: он используется для замены на `/номер карточки/`. Каждый временной блок является отдельным Telegram-сообщением. Если подразделение не распознано, перед обычным текстом добавляется красный заголовок `НОВОЕ ИЛИ ОШИБОЧНОЕ ПОДРАЗДЕЛЕНИЕ` и, при достаточно близком совпадении, подсказка. Подсказка не меняет маршрут автоматически.

У каждого Telegram-получателя хранится собственный редактируемый шаблон. Он находится не в отдельном файле, а в защищённой серверной конфигурации `data/server-config.dat` и показывается в форме получателя. Программа проверяет обязательные метки до сохранения; стандартный вариант можно восстановить одной кнопкой.

## Редактирование перехвата

EAVC разрешает изменять запись только пока смена открыта. При закрытой смене серверная команда EAVC возвращает ошибку `Смена закрыта (только просмотр)` до изменения строки в SQLite. Поэтому клиент не видит новой версии и ничего не отправляет ни в Telegram, ни в Word.

Для допустимой правки открытой смены в Python-клиенте менялся отпечаток записи, клиент повторно передавал полное состояние бланка, а Python-сервер хранил соответствие `временной блок → Telegram message_id`. Новый блок вызывал `sendMessage`, изменённый — `editMessageText`, удалённый — `deleteMessage`. Если исходное сообщение Telegram удалили вручную либо Telegram отвечал, что его уже нельзя редактировать, Python-сервер создавал заменяющее сообщение. По утверждённому новому правилу Go-сервер замену не создаёт: он записывает предупреждение в журнал, чтобы старая правка не выглядела в топике как новый перехват. Word при этом обрабатывается независимо.

Go-версия использует ту же модель. Разница только в доставке до сервера: снимок сначала попадает в долговечную очередь клиента и передаётся зашифрованным файлом. Состояние Telegram хранится отдельно для каждого направления, UUID записи EAVC и темы. Поэтому правка в Аэродроме не смешивается с Шабашкой, а перезапуск сервера не забывает `message_id`.

## Формат Word для сети 313

Один временной блок EAVC создаёт один DOCX и получает постоянный номер `СТНД`. Имя по умолчанию:

```text
СТНД17 2 об 3 обр ОсН НГ (отложенный режим) - 313.docx
```

Внутри документа сохраняется структура предоставленного файла `word_template.docx`. Номер и описание позывного берутся из той же карточки EAVC, что и для Telegram, поэтому `/номер/` в обоих результатах совпадает:

```text
ДНЕПРОПЕТРОВСКОЕ НАПРАВЛЕНИЕ

Радиосеть 2 об 3 обр ОсН НГ (отложенный режим) - 313
159.5750 МГц (гр. ID 3 AES-256)
18.10.2026г.

1.«Марс» (id: 783693) – военнослужащий 2 об 3 обр ОсН НГ (отложенный режим), мужской голос, украинская речь;

03:51
/1/ На приём.

Дежурный оператор: Позывной
Старший смены МГ 1: Позывной
```

Шаблон `word_template.docx` остаётся внешним файлом и является источником истины для оформления. Сервер не создаёт вместо него новое тело документа: он заменяет только явно расставленные метки, поэтому заголовки, таблицы, подписи, интервалы и шрифты меняются самим пользователем в Word. Стандартный шаблон поставки подготовлен из предоставленного эталона и содержит обязательные метки для данных перехвата.

При изменении существующего блока Go-сервер сохраняет номер СТНД, перезаписывает тот же файл и добавляет точную отметку старой Python-версии `(отредактировано)`. При изменении названия подразделения файл переименовывается с сохранением номера. Если блок удалён из EAVC, соответствующий DOCX удаляется из папки. Неизменённый блок повторно не выгружается, даже если принимающая сторона уже забрала файл из сетевой папки.

`39-ка` — получатель сетевой папки. `313` — подпись отправляющей радиосети в имени и тексте документа. Go-сервер не создаёт локальный архив всех DOCX и не очищает удалённую папку по таймеру: принимающая сторона сама забирает файлы. На сервере остаются только шаблон, ограниченное состояние номеров и ротируемый журнал.

## Отложенный режим

`(отложенный режим)` — часть отображаемого названия, которую оператор вручную добавляет в EAVC, чтобы показать, что перехват отправлен позже. Это не отдельная позиция и не запрет отправки.

Для маршрутизации Go-сервер отбрасывает только это окончание и находит правило базового подразделения. Для Telegram, имени файла и содержимого Word используется исходное полное название. Отложенный перехват проходит по тем же направлениям, что обычный: например, известная позиция Аэродрома отправляется в свой топик и создаёт DOCX для сети 313.

Проверенный Python-сервер сопоставлял название строго после приведения регистра, кавычек и пробелов. Во всех найденных рабочих и исходных `config.json` темы 24 и 28 записаны без окончания: `503 обмп 38 обрмп` и `управление 25 овдбр`. Одновременно эти темы были внесены в `deferred_topic_ids`, поэтому сервер отвечал ошибкой «правило отправки не задано». То есть предоставленная Python-сборка не могла корректно провести вариант с окончанием `(отложенный режим)`. В Go-версии это исправлено: окончание не участвует только в поиске маршрута, но полностью сохраняется в Telegram и Word.

## Существенные отличия новой версии

- вместо открытого HTTP по локальной сети используется зашифрованный Telegram-транспорт;
- события старше 30 минут не начинают доставляться;
- зависшая точка не теряет данные, а зависшее направление не повторяет уже успешные направления;
- маршруты версионируются и редактируются в интерфейсе без пересборки;
- неизвестные позиции направляются только в явно настроенное направление проверки;
- завершённые записи локальных очередей хранятся 30 суток для диагностики и затем автоматически удаляются; журналы имеют ограничение по размеру;
- принятые и помещённые в карантин файлы `.icevent` удаляются из транспортной группы после сохранения результата на сервере;
- обозначение радиосети настраивается отдельно у каждого получателя Telegram и Word.

Ни `39`, ни `313` не зашиты в форматтер: администратор указывает нужное обозначение отдельно для каждого Telegram- или Word-получателя.
